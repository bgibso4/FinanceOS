Travel

Global constraints

These apply to every task, whether or not the task repeats them.

  • DRY > YAGNI > SOLID, in that order. Extract shared code instead of copying it; build nothing no task needs; no interface with only one implementation. Classes for services that hold injected dependencies (prisma, Clock, currency), wired only in createTravelServices; tests inject fakes, never vi.mock of domain modules.
  • One transaction editor: every transaction row anywhere in Travel opens the shared TransactionDrawer through useTransactionDrawer. No modals; drawers push (DRAWER_PUSH_CLASS).
  • Design tokens only (src/app/globals.css, light and .dark); no new colours. Tonal shades come from --accent via color-mix (Task 10's tonalShade).
  • Schema changes with npx prisma db push (never migrate dev, it fails with P3006), then npx prisma generate.
  • Every new table and column goes into cloud sync export, import, delete order and the Zod payload (src/lib/cloud-sync/sync.ts, types.ts).
  • Amounts: negative = spend, positive = money in. Transaction dates are UTC DateTime; trip dates are YYYY-MM-DD strings, inclusive.
  • Every Travel figure is net (sum of signed amounts, shown as spend = −sum) and converted to the base currency with convertAmount via loadCurrencySettings.
  • Split parents are never assigned, suggested or counted (isSplitParent: false).
  • The Travel group is the top-level expense category named Travel; Flights and Lodging are its children whose names contain Flights / Lodging (case-insensitive). No group → travel rules match nothing. Income = category type === 'income' or a child of one.
  • Vendor-neutral names. console.log is a lint warning: use console.warn/console.error only.
  • npm run check has 0 errors before every commit; the commit hook runs lint-staged. docs/ is gitignored: git add -f for docs.
  • Commits end with Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>. One PR against main at the end.

Review focus

The ways a person is most likely to break this that the spec doesn't spell out. Each has a test in the task that owns it.

  1. A trip that crosses a year boundary, or bookings made the year before (December flights for a February trip; a Dec 28 – Jan 3 trip). All of the trip counts in its start year; nothing is counted twice or dropped. Test: Task 5 countsWholeTripInItsStartYear, bookingBeforeTripExistsCountsByDateThenMoves.
  2. A transaction already on another trip offered or added twice (two trips overlap; a stale suggestion list). It must never move silently: assign only takes rows whose tripId is null. Test: Task 7 assignSkipsTransactionsAlreadyOnAnotherTrip; Task 6 excludesTransactionsOnAnyTrip.
  3. Deleting a trip, or splitting/unsplitting a transaction on one. Transactions survive with tripId null and dismissals go; split parts inherit the parent's trip; unsplit keeps the trip. Test: Task 7 deleteTripKeepsTransactions; Task 7 splitPartsInheritTripAndUnsplitKeepsIt.
  4. Empty and degenerate data: a year with no trips, a trip with no transactions, a one-day trip, no Travel group, end before start. No NaN, no crash, a clear 400 for bad dates. Test: Task 5 emptyTripHasZeroPerDay, oneDayTripCountsOneDay; Task 6 noTravelGroupSuggestsOnlyOtherAndMoneyIn; Task 7 rejectsEndBeforeStart.
  5. Mixed currencies (CAD rows on a USD base). Totals, bars and budget use converted amounts; a missing rate behaves as convertAmount already does. Test: Task 5 convertsForeignAmountsToBase.
