Analytics: any period, with filters

Analytics shows any period (month, 3 months, year, custom) stepped with arrows, compared with a chosen period, narrowed by a floating filter panel, with a line chart over time. Built on today's page, drawer and counting rules.

ArchitectureTwo pure modules carry the rules: src/lib/analytics-period.ts (ranges, comparisons, stepping, labels) and src/lib/analytics-query.ts (the URL). One shared filter module serves both APIs. dashboardAnalytics gains an explicit comparison range, and a new /api/analytics/daily returns netted spend per day and category from the same loader, so the client builds every chart series with src/lib/analytics-series.ts. New components live in src/components/analytics/; the page composes them.
Tech stackNext.js App Router, React 19, TypeScript, Prisma + SQLite, Tailwind, Recharts 3, vitest + Testing Library.
Specdocs/superpowers/specs/2026-11-07-analytics-periods-and-filters-design.html (published: https://claude.ai/artifact/Kz54fXf5ubLoHamopN8tLw). Mock: ~/Documents/FinanceOS-design-archive/design-mocks/analytics-filters.html. Executors read both.

Waiting on you

Calls I made while planning that the design didn't settle. Each is easy to change before its task starts; veto any you don't like.

  • P1URL names
    period=month|3m|year|custom, at=YYYY-MM (the last month of the period; Dec for a year), from/to for custom, vs=prev|lastYear|none, and repeated category, account, tag, plus merchant. Defaults (this month, prev, no filters) are left out of the address.
  • P2Daily data, client-built series
    The server returns netted spend per (day, category) for the period and the comparison; the browser buckets, accumulates and splits it. One loader on the server, so the chart can't disagree with the figures.
  • P3The chart's comparison runs to its month end
    For the current month, the figures compare day for day (Oct 1–7), but the dashed line fetches all of October so it can show where October ended.
  • P4Year list
    Clicking the label in Year mode lists the current year and the four before it.
  • P5Per day vs per month
    The third figure is Per day exactly when the chart is daily (the period spans under two calendar months), so the two always agree.
  • P6Merchant typing
    The merchant box applies 300 ms after you stop typing, so each keystroke doesn't refetch.
  • P7PIE_COLORS moves
    To src/lib/chart-colors.ts, re-exported from chart-renderer.tsx, so library code can use it without importing a component.
  • P8applyFilters goes
    It has no callers outside its own tests. The shared filter module replaces it.
  • P9Comparison percent with no history
    When the comparison is $0, the change shows the dollar difference and "—" for the percent, never ∞% or NaN.
  • P10Daily data ignores the category filter
    The daily request carries account, tag and merchant filters but not categories; the browser applies the category picks. That gives the panel each group's total for the period, so you can see what you'd add before ticking it.

Global constraints

These apply to every task, whether or not the task repeats them.

  • DRY > YAGNI > SOLID, in that order. Extract instead of copying; build nothing no task needs; no interface with one implementation.
  • Spec: docs/superpowers/specs/2026-11-07-analytics-periods-and-filters-design.html. Mock (layout "C · Right side", floats over): ~/Documents/FinanceOS-design-archive/design-mocks/analytics-filters.html. The mock's toolbar strip and other layouts are not the design.
  • Date rule (src/lib/dates.ts): transaction dates are calendar days (YYYY-MM-DD), never converted. Today is localDay(). All period maths works on YYYY-MM-DD strings.
  • Counting rules unchanged: transfers, split parents and offsets out; cash-flow accounts only; linked returns netted against their purchase; credits netted against their category; base currency via toBase.
  • dashboardAnalytics also serves home, Reports and trailing-12: without a comparison range its response must not change.
  • One transaction editor: rows open TransactionDrawer via useTransactionDrawer. The filter panel and the drawer are never open together.
  • Design tokens only (src/app/globals.css), light and dark. Motion respects motion-reduce.
  • Tests never touch prisma/dev.db: integration tests use tests/helpers/db.ts. In zsh list test files explicitly (no $T). Use findBy… after fetches.
  • Branch feat/analytics-periods-filters off main; one PR against main. Commit after each task. The spec and this plan are committed with git add -f (docs/ is git-ignored).

Review focus

The ways a person is most likely to break this that the spec doesn't spell out. Each has a test in the task that owns it.

  1. Month ends and short months. Viewing the current month on Mar 30 compares with Feb 1–28, not Mar 2. Test: Task 2 clampsToShortMonth.
  2. Late evening. At 10:30pm on Nov 30 in New York (already Dec 1 in UTC), a fresh visit opens November. Test: Task 3 defaultsToLocalMonthLateEvening.
  3. A group only partly ticked. Golf with only Green Fees ticked, plus Clothing, is two picks (Green Fees, Clothing), not Golf. Test: Task 6 partlyTickedGroupSplitsIntoCategories.
  4. Comparing with a period before your history. Shows $0 and "—" for the percent, and the dashed line flat at 0; no NaN. Test: Task 8 emptyComparisonShowsZeroAndDash.
  5. Answers arriving out of order. Stepping quickly or typing a merchant fires several requests; only the latest may land. Test: Task 10 staleResponseIsIgnored.
