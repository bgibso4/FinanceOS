Automatic sync and daily exchange rates

The production server syncs every connected bank and investment account, refreshes prices, and records each day's CAD→USD rate on its own every 4 hours; every amount converts at its own day's rate.

ArchitectureRates: dated ExchangeRate rows read through one RateBook, filled by ExchangeRateHistory through the existing price-provider gateway (getDailyHistory + a new fxSymbol). Sync: route bodies move into src/lib/connection-sync.ts; runSyncPass (rates → accounts → prices → record) takes its steps as injected functions; a scheduler started from instrumentation.ts only decides when to call it.
Tech stackNext.js 16 App Router, React 19, TypeScript, Prisma 5 + SQLite, yahoo-finance2 (behind PriceProvider), vitest + Testing Library.
Specdocs/superpowers/specs/2026-11-08-auto-sync-and-fx-design.html (published: https://claude.ai/artifact/B193LGezqwJ7n5GkjYzhUL). Executors read it.

Waiting on you

Calls I made while planning that the design didn't settle. Each is easy to change before its task starts; veto any you don't like.

  • P1Rates are dated rows in ExchangeRate
    Add date DateTime (UTC midnight, like SecurityPrice.date); unique becomes (fromCurrency, toCurrency, date). The one hand-typed row is dropped by the schema push; the first pass backfills real history.
  • P2One gateway: the existing price provider
    PriceProvider gains fxSymbol(from, to); Yahoo answers `${from}${to}=X`. Rates come from the existing getDailyHistory, no quote call and no second client; today's bar is re-read each pass.
  • P3Wired in the investments composition root
    createInvestmentServices is the one place the provider is wired, so the rate service is built there as fxRates.
  • P4RateBook replaces every rate map
    One class answers "rate from A to B on day D". parseExchangeRates, loadFxRates (price-book) and getDefaultExchangeRates go; Map<string, number> rate parameters become RateBook.
  • P5Day omitted means latest
    convertAmount and toBase take an optional day (YYYY-MM-DD). Dated amounts pass their day; "now" amounts (current balances) pass nothing and get the latest stored rate.
  • P6Rate edit routes go
    With the Settings rate read-only, POST /api/exchange-rates and DELETE /api/exchange-rates/[id] are deleted (no callers). GET returns the latest rate per pair; POST /api/exchange-rates/refresh runs the fill. This replaces the design's "routes stay" call, which dated rows made impossible.
  • P7Backfill starts at first use
    Per pair, from the earliest transaction or stored balance on an account in that currency; later passes start at the last stored day. Sanity: reject non-finite, ≤ 0, or more than 20% away from the previous stored day.
  • P8Last-pass record on UserSettings
    scheduledSyncFinishedAt DateTime? and scheduledSyncFailures String? (JSON array of failed step names). Written only when a pass finishes.
  • P9Folder src/lib/scheduled-sync/
    Not "auto-sync": src/lib/cloud-sync/auto-sync.ts already names the cloud backup. Switch: runs only when NODE_ENV === 'production' and SCHEDULED_SYNC is not off.
  • P10Old cloud backups still restore
    An exported rate gains date; a backup without it imports with date = the row's updatedAt day.

Global constraints

These apply to every task, whether or not the task repeats them.

  • DRY > YAGNI > SOLID, in that order; principal-engineer skill loaded. One sync path, one rate lookup, one provider gateway. No interface with one implementation unless a test needs the seam.
  • Spec: docs/superpowers/specs/2026-11-08-auto-sync-and-fx-design.html.
  • Vendor names (Plaid, Teller, Yahoo) only at integration boundaries; neutral terms elsewhere.
  • Date rule (src/lib/dates.ts): transaction dates are calendar days, never converted; rate days match them as YYYY-MM-DD. Real moments (last run, as of) show local.
  • Tests never touch prisma/dev.db (use tests/helpers/db.ts) and never call a real bank or price provider. Schema changes reach dev.db only in Task 8, with Ben, via prisma db push after a backup.
  • Port 3000 is Ben's production server: never touch it. Agents' dev servers run on a copy of dev.db, and the scheduler never runs outside production.
  • Only console.warn/console.error. Design tokens only, light and dark. In zsh list test files explicitly. Use findBy… after fetches.
  • Branch feat/auto-sync-fx; one PR against main, opened only when Ben says. Commit after each task (trailer Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>). Spec and plan committed with git add -f.

Review focus

The ways this is most likely to bite that the spec doesn't spell out. Each has a test in the task that owns it.

  1. The laptop was off for days. The first pass back fills every missing day before syncing accounts. Test: Task 3 fillsGapAfterDowntime.
  2. Weekends, holidays, and today before a bar exists. Use the latest earlier day, never 1:1. Test: Task 1 weekendUsesEarlierDay.
  3. A transaction older than the rate history. Use the earliest stored rate. Test: Task 1 beforeHistoryUsesEarliest.
  4. An agent's dev server on a copy of dev.db. Never starts the scheduler, so no real bank call advances a cursor on a copy. Test: Task 5 neverStartsOutsideProduction.
  5. Clicking Sync while a pass runs. The click waits for the pass's lock on that connection; no double import. Test: Task 5 passAndRouteShareTheLock.
