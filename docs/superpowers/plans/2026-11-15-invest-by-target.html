Invest by target: implementation plan

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Load the principal-engineer skill before writing code.

GoalSettings → Investing Targets holds class and region targets. On the Investments page, an Invest drawer turns an amount into a list of funds to buy that moves the counted portfolio toward those targets.
ArchitectureThree tables (classes, regions, countries), plus each security's target and each account's inclusion. One pure module, allocation.ts, owns the math: final targets, then trades. The client also uses it for live previews. TargetSettingsService reads and saves the setup. TargetPlanner reads holdings through the existing CurrentHoldingsReader, so its values match the Investments page.
Stack · SpecNext.js, React 19, Tailwind, Prisma/SQLite, Zod, Vitest + Testing Library. Spec: docs/superpowers/specs/2026-11-15-invest-by-target-design.html. Mock: ~/Documents/FinanceOS-design-archive/design-mocks/investments/invest-by-target.html (v3).

Global constraints

  • Apply schema changes with npx prisma db push; never migrate dev. The test database pushes the schema itself (tests/helpers/db.ts).
  • Percentages are stored as numbers out of 100 (pct, weightPct, tiltPct). Everything computed is a fraction from 0 to 1 (target, shareOfClass, currentPct, afterPct). Tilt must be above −100.
  • At most one class has splitByRegion: true. Its funds need a region; every other class's funds have none.
  • The starting setup, copied exactly:
    • Classes: Stocks 80 (split by region), Fixed income 15, Crypto 5.
    • Regions: US, Developed ex-US, Emerging. Tilt 0, no "buy with" fund.
    • Countries: USA 55.9 → US.
    • Developed ex-US: Japan 7.4, UK 4.1, France 2.9, Switzerland 2.6, Germany 2.6, Australia 2.1, Other developed 2.77, Canada 3.55.
    • Emerging: China 5.4, Taiwan 1.7, Other emerging 8.32.
    • These final targets are an acceptance value: US 0.4502, Developed ex-US 0.2257, Emerging 0.1242, Fixed income 0.15, Crypto 0.05 (4 decimal places).
  • Amounts are in the base currency (UserSettings.baseCurrency, default USD). The buys add up to the amount to the cent, with any rounding remainder on the largest trade. A price is stale when it's more than 3 days older than today.
  • Copy, exactly (from the approved mock):
    • Tab: "Investing Targets", at /settings?tab=targets, after Securities.
    • Card titles: "Asset classes", "Stocks by region" (uses the split class's name: "<name> by region"), "Countries", "Funds", "Accounts".
    • Drawer:
      • Title "Invest"; amount label "Amount to invest"; switch "Allow sells".
      • Switch hint when off: "Off: the amount only goes to targets below." When on: "Full rebalance: sells what's over target so every target lands on it."
      • Card titles: "Buy list" / "Rebalance" / "Where you stand".
      • Row text: "Pick a fund to buy", "over target", "Sell $x" (then "pick from below"), "What you hold here", "No price yet".
      • "Left out", then the footer "Nothing is saved. Your next sync brings in the buys." and "Edit investing targets →".
      • Empty state "Set your investing targets first".
  • No vendor names outside integration boundaries. Ticker strings in tests and defaults are fine.
  • No npm run build, because the production server runs from this checkout's .next. For the browser check use npx next dev -p 3100.
  • npm run check and the touched test files pass at the end of every task, and every task ends with a commit.

Review focus

Inputs the spec implies but doesn't spell out. Each has a test in the task named.

  1. A fund left half-assigned (its region was deleted, or its class stopped splitting) is treated as Not counted and listed under Left out. It must not throw or count toward the wrong target. Test in Task 4.
  2. Targets that can't add up (all classes at 0, or the split class with no country weight) give ready: false with a reason. They must never produce NaN or a buy list that doesn't sum to the amount. Tests in Tasks 2 and 4.
  3. A bad amount (-5, abc, 1e12) gets a 400 from the plan route. In the drawer, "1,000" and "$1,000" parse as 1000, and an empty field shows "Where you stand". Tests in Tasks 4 and 6.
  4. A "buy with" fund with no price yet shows dollars with "No price yet" and no share count. Test in Task 4.
  5. A cloud-sync payload from a device without targets imports without failing. Targets then default on next load, and accounts stay included. Test in Task 1.

Task 2 · Target math

Files: create src/lib/investments/targets/allocation.ts and tests/unit/lib/investments/target-allocation.test.ts.

Produces. Pure and client-safe: no Prisma, no server imports.

  • type ClassInput = { id: string; name: string; pct: number; splitByRegion: boolean; buySecurityId: string | null }
  • type RegionInput = { id: string; name: string; tiltPct: number; buySecurityId: string | null }
  • type CountryInput = { weightPct: number; regionId: string }
  • type TargetSetup = { classes: ClassInput[]; regions: RegionInput[]; countries: CountryInput[] }
  • type FinalTarget = { key: string; classId: string; regionId: string | null; name: string; className: string | null; buySecurityId: string | null; marketWeightPct: number | null; shareOfClass: number | null; target: number }. For a region, name is the region and className is the split class's name. For any other class, name is the class and className is null.
  • targetKey(classId: string, regionId: string | null): string returns classId, or `${classId}:${regionId}` for a region.
  • finalTargets(setup: TargetSetup): FinalTarget[], in class order with each region in its own order.
  • targetTotals(setup: TargetSetup): { countryWeightPct: number; classPct: number }
  • planTrades(rows: { key: string; current: number; target: number }[], amount: number, sells: boolean): Record<string, number>. It throws a RangeError unless the targets add to 1 (±1e-6).

  1. Tests:
    • starting setup gives the acceptance targets: build the starting setup inline (Global constraints). The targets match 0.4502 / 0.2257 / 0.1242 / 0.15 / 0.05 to 4 places, and the US shareOfClass is 0.5627.
    • tilt then scale within the class: US +20 gives a US share of 0.6070 (= 55.9×1.2 / (55.9×1.2 + 28.02 + 15.42)).
    • class percentages scale: classes of 40 / 40 give targets of 0.5 each, and targetTotals gives classPct 80.
    • a class at 0 has target 0, and the other targets still add to 1.
    • worked example: current 4700 / 2000 / 1300, targets 0.6 / 0.25 / 0.15, amount 1000, sells off gives 700 / 250 / 50.
    • an overweight target leaves the rest to share by gap: current 0 / 1000 / 0, targets 0.4 / 0.4 / 0.2, amount 500 gives the gaps 600 / −400 / 300, so G = 900 and the buys are 333.33 / 0 / 166.67.
    • no overweight fills every gap exactly: current 100 / 0, targets 0.5 / 0.5, amount 300 gives 100 / 200. With no negative gaps, G always equals the amount, so the "split the extra by target" branch only ever moves rounding cents.
    • overweight gets 0 with sells off, and no trade is negative.
    • sells on lands on target: current 900 / 100, targets 0.5 / 0.5, amount 0 gives −400 / 400.
    • buys add up to the amount: amount 1000.01 over three equal targets adds up to exactly 1000.01, with the largest trade taking the remainder.
    • empty portfolio splits by target.
    • targets not adding to 1 throw.
  2. Run npx vitest run tests/unit/lib/investments/target-allocation.test.ts. It FAILS because the module is missing.
  3. Implement it.
    • A region's share is weight × (1 + tilt/100) over the sum of those for every region. Each class's fraction is pct over the sum of all class percentages.
    • A split class with zero total region weight gives its regions target 0.
    • A zero class sum gives every target 0.
    • In both cases the caller detects that the targets don't add to 1.
    • planTrades follows spec §3: gap = target × (Σcurrent + amount) − current. Sells off: fill the positive gaps, then split any extra by target, or split the amount in proportion to the gaps if it's smaller. Round to cents, and put the remainder on the trade with the largest absolute value.
  4. Run the file. It PASSES.
  5. Commit: feat(investments): target allocation math.
