Outside budget: implementation plan

For agentic workers: REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Load the principal-engineer skill before writing code.

GoalA per-transaction "outside budget" flag that keeps real spending out of monthly views but counts it in Cash Flow and tag totals. Bank sync stops marking unpaired "transfers".
ArchitectureOne boolean column. One optional filter, includeOutsideBudget, carried by FilterParams and applied in loadPeriodTransactions, the single spending loader. Callers that should count one-offs (Cash Flow, tag totals, the Analytics toggle) ask for it. Sync's only path to a transfer becomes pairing, and every pairing write also clears the flag.
Stack · SpecNext.js 16, React 19, Tailwind 3.4, Prisma/SQLite, Vitest + Testing Library. Spec: docs/superpowers/specs/2026-11-13-outside-budget-design.html. Mock: ~/Documents/FinanceOS-design-archive/design-mocks/outside-budget.html (v2).

Global constraints

  • Field: Transaction.isOutsideBudget Boolean @default(false). Apply it to prisma/dev.db with npx prisma db push; never migrate dev. The test database pushes the schema itself (tests/helpers/db.ts).
  • A row is never both isTransfer and isOutsideBudget. Any write that sets isTransfer: true also sets isOutsideBudget: false.
  • Filter: FilterParams.includeOutsideBudget?: boolean, sent over the wire as outside=1. Absent or any other value means false.
  • Default is to leave the rows out: Analytics, Dashboard, Reports → Monthly Detail, and monthlySnapshot. Included: Reports → Cash Flow (/api/reports/trailing-12-months), spendingByTag, the Analytics toggle, and links from tagCostHref.
  • Picking a tag in Filters does not turn the toggle on.
  • Copy, exactly:
    • Drawer tick box: label "Outside budget", hint (only when ticked) "Left out of your monthly numbers".
    • Panel switch: label "Include outside budget", hint "Spending you kept out of your monthly numbers".
    • Chip: muted "Incl." and the text "outside budget".
    • List suffix: " · Outside budget".
  • Tags in the filter panel is always collapsible (the "more than 8" rule goes away).
  • No npm run build: the production server runs from this checkout's .next. For the browser check, use npx next dev -p 3100.
  • npm run check and the touched test files must pass, and commit after each task. Vendor names appear only at integration boundaries.

Review focus

Inputs the spec implies but doesn't spell out. Each has a test in the task named.

  1. A ticked row that later gets paired (you mark the first side outside budget, then its partner arrives) becomes a transfer with the tick cleared. Test in Task 3.
  2. An old cloud-sync payload without the field (another device on the previous version) imports with isOutsideBudget: false instead of failing validation. Test in Task 1.
  3. A tag filter with the toggle off leaves that tag's outside-budget rows out. Only tagCostHref and the toggle bring them in. Test in Task 2.
  4. An old Analytics link or outside=0 / outside=yes parses as off, and an off query writes no outside param. Test in Task 4.
  5. A transfer you marked by hand that the bank re-sends (a modified update) stays a transfer, because sync no longer writes isTransfer from the label. Test in Task 3.
