Architecture

  • Layers, each depending only on the one below through an interface:
    • Domain (src/lib/price-index/types.ts, months.ts, series.ts): vendor-free types — IndexRegion, MonthKey, IndexObservation — and the pure IndexSeries that answers annual change, monthly change and adjustment factors. Runs on server and client.
    • Sources (src/lib/price-index/sources/): PriceIndexSource implemented once per agency. Each adapter owns its vendor request and response schema privately and returns only IndexObservation[]. HTTP is injected (fetch), so tests use recorded responses.
    • Store (store.ts): PriceIndexStore, the only code that touches the PriceIndexMonth table.
    • Service (history.ts): PriceIndexHistory.fill() decides what to ask each source, validates, and saves through the store. It never sees Prisma or a vendor payload.
    • Composition root (services.ts): the one place real sources, store and clock are wired.
  • Consumers: the sync pass (new inflation step), GET /api/price-index, Reports (IndexSeries.factor), and the General tab.
  • Rates reuse the existing ExchangeRate rows; a pure summarizePair adds the sparkline, 1-year change and month-end table to GET /api/exchange-rates.
  • UI: the General tab moves out of the 4,600-line Settings page into src/components/settings/general/, built from reusable SettingsGroup / SettingsRow / ExpandableRow pieces so later settings are one more row.

Planning calls

Decisions the spec left to the builder, settled here so every task agrees.

  • P1Months are "YYYY-MM" strings
    Stored and passed as MonthKey. No time zones, sorts as text, matches how both agencies publish.
  • P2Table PriceIndexMonth
    id, region String, month String, value Float, createdAt, updatedAt, @@unique([region, month]). InflationRate is dropped. UserSettings gains inflationRegion String @default("US").
  • P3Missing months are absent, not failures
    The US series has no October 2025 (the API returns "-"). Adapters drop non-numeric months; figures that need a missing month are null and show "—". A response with an error status is a failure.
  • P4Endpoints
    US: POST https://api.bls.gov/publicAPI/v1/timeseries/data/ with {"seriesid":["CUUR0000SA0"],"startyear","endyear"}, at most 10 years per request. Canada: GET https://www150.statcan.gc.ca/t1/wds/rest/getDataFromVectorByReferencePeriodRange?vectorIds="41690973"&startRefPeriod=YYYY-MM-01&endReferencePeriod=YYYY-MM-01. Both verified 2026-11-08.
  • P5When to ask
    Skip a region when its last stored month is last month or later (nothing newer can exist). Otherwise re-read from 3 months before the last stored month (revisions) to the current month. First fill starts 12 months before the earlier of the first net-worth snapshot and 12 months ago, so Settings always has 24 months.
  • P6Sanity bound
    Reject a fill (write nothing for that region) if any value is non-finite or ≤ 0, or moves more than 5% from the previous observation in the same answer or the store.
  • P7Plain-SVG sparkline on the existing geometry
    One HoverSparkline built on chartGeometry (src/components/investments/chart-geometry.ts). No Recharts here.
  • P8One row component
    ExpandableRow serves both rate and inflation rows; the inflation row passes its radio as a leading slot.
  • P9Base currencies in one list
    BASE_CURRENCIES in src/lib/currency.ts feeds both the select and the settings route's validation.

Global constraints

  • principal-engineer loaded by every implementer and reviewer. DRY > YAGNI > SOLID.
  • Integration isolation (Ben, 2026-11-08): vendor request/response types and Zod schemas live only inside their adapter file and are never exported; everything outside sources/ sees only IndexObservation / MonthKey / IndexRegion. Services depend on interfaces (PriceIndexSource, PriceIndexStore, Clock), constructed in services.ts only. Prisma appears in store.ts and the composition root, not in history.ts.
  • Vendor names only at the edges: BLS / Statistics Canada names appear in adapter files and the attribution strings; elsewhere "consumer price index".
  • Follow the approved mock for layout, wording and behaviour. Design tokens only, light and dark; no emoji in the General tab; accent only on sparklines, the selected radio, "In use" and Save changes.
  • Date rule: months are calendar months, never time-zone converted; real moments ("as of 7:20 am", "fetched Nov 8") show local via fmtMoment.
  • Tests never touch prisma/dev.db (use tests/helpers/db.ts), never call a real statistics API, bank or price provider. In zsh list test files explicitly. Use findBy… after fetches. Each implementer runs every test file touching changed modules plus npm run typecheck.
  • Only console.warn / console.error. Schema changes via prisma db push; the live database only in Task 9, with Ben, after a backup.
  • Port 3000 is Ben's production server: never touch it. Production runs a build made from this checkout, so never run npm run build or next build in the repo (builds go in a scratch export) and never restart production. The scheduler never runs outside production; never run a bank sync on a database copy.
