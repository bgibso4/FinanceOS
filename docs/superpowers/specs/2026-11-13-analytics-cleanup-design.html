Analytics cleanup

This started as "how do I track the cost of a big purchase?" The answer turned out to be the tags you already have, plus Analytics, which already filters by tag and draws a running total. So the work is cleanup: the filter chips look broken in dark mode, the filter panel makes you scroll past every category and account, and tags have nowhere to show what they cost. Fixing the chips also fixes a colour bug that has been quietly affecting about 75 places across the app.

1 · Colour tokens

The root cause of the chips' bright border, and of ~75 other tints across the app.

  • The bug. Tailwind 3 can't apply an opacity modifier to an arbitrary var() colour, so classes like border-[var(--accent)]/30 and bg-[var(--accent)]/10 are never generated. Elements fall back to the default border colour (light gray). Confirmed with the Tailwind CLI.
  • The fix. In tailwind.config.js, define each themed colour so it accepts opacity, using Tailwind's <alpha-value> placeholder with color-mix: accent: 'color-mix(in srgb, var(--accent) calc(<alpha-value> * 100%), transparent)'. Then border-accent/30 works.
    • Tokens needed: accent, green, red, yellow, bg-base, and tag-blue … tag-yellow (9).
    • Rewrite every [var(--x)]/N usage to the named token (accent/30, tag-blue/15, …). Most are in tag-input.tsx, design-system.ts, the Settings page and transaction-table.tsx.
    • Colours without a modifier keep working unchanged.
  • Guard (M4). A unit test scans src/**/*.{ts,tsx} and fails on any [var(--…)]/N.

2 · Filter chips

The row under the Analytics title (FilterChips).

  • Always-present chips (Period, vs): bg-elevated fill, a 1px --border edge, 8px radius. The label word ("Period") is muted and the value is primary.
  • Chips you added (Category, Account, Tag, Merchant): the same, but with an accent/35 edge, plus the existing ✕.
  • No other changes: same order, the same capped text, and ✕ clears the filter as it does today.

3 · Filter panel

The floating card that opens from the funnel button (FilterPanel).

  • Collapsible sections. Categories and Accounts are collapsible; Tags is too once it passes 8 tags (M5). The whole header row toggles it, with a chevron on the right that rotates when open.
    • The header shows the picks in accent ("Dining +1"), or, muted, "Any · 52" when nothing is picked.
    • Every collapsible section starts closed each time the panel opens. Open state lasts while the panel stays open.
    • Keyboard: the header is a button with aria-expanded; Enter and Space toggle it.
  • Groups fold inside Categories. With Categories open, each group shows a single row (tick box, name, total) and a small chevron. Its children show when you open it, when any of them is picked, or while you're searching.
  • Alphabetical. Groups A–Z, then categories A–Z within each group; accounts A–Z. The sort key skips leading emoji and symbols and ignores case (M3). Ungrouped categories sort in among the groups.
  • Spacing. 12px between a section header and its contents, 10px under the search box, and 16px of padding above and below each section. Period, Compared with and Merchant also get the 12px.
  • Period, Compared with and Merchant are otherwise unchanged.

4 · Settings → Tags

The existing tags table.

  • Total column, right-aligned in monospace. It's each tag's all-time spend as Analytics counts it (M1). /api/tags?withCounts=true also returns total, firstDate and lastDate, computed by the same spending code Analytics uses (no second formula).
  • "See cost →" on each row links to /analytics?period=custom&from=<firstDate>&to=<lastDate>&vs=none&tag=<name>, built with toSearchParams (M2). A tag with no transactions shows no link.
  • Create, edit, colour and delete stay as they are.
